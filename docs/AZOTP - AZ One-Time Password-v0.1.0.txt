VERSION
------------------------------------------------------------
v0.1.0

TYPE
------------------------------------------------------------
Reference Architecture / Protocol Specification

============================================================

OVERVIEW
------------------------------------------------------------

AZOTP is a deterministic, human-centered OTP protocol
designed for trusted-device mobile ecosystems.

It prioritizes:
- usability
- low cognitive load
- fast human verification
- app-switch resilience
- mobile-first interaction

AZOTP is NOT a replacement for:
- WebAuthn / Passkeys
- OAuth2 / OIDC
- hardware security keys
- high-assurance identity systems

============================================================

CORE OTP MODEL
------------------------------------------------------------

OTP FORMAT:
- 4 alphabetic characters (a–z)

BASE:
- 26

CASE HANDLING:
- internal: lowercase
- verification: case-insensitive
- display: uppercase recommended

EXAMPLES:
- KQMX
- WZFA
- BQKE
- TVRP

TOTAL SPACE:
26^4 = 456,976 combinations

============================================================

DERIVATION (REFERENCE MODE)
------------------------------------------------------------

hash = blake3(azotp_server_secret + context)
otp  = base26(hash)[0:4]

============================================================

RANDOM MODE
------------------------------------------------------------

secure_random_bytes → base26 → first 4 chars

============================================================

AZOTP - BINDING
------------------------------------------------------------

AZOTP Binding is a standalone pre-authentication
contextual binding system.

CORE INPUTS:
- provider
- device_id
- session
- nonce

PROVIDER EXAMPLES:
- zalo
- google
- apple
- facebook

CONTEXT EXAMPLE:

provider:zalo|device:web:abc123|session:s7d9|nonce:p4t2|t:202605150930

PURPOSE:
- provider isolation
- device isolation
- session isolation
- replay prevention
- deterministic OTP generation

============================================================

SECURITY MODEL
------------------------------------------------------------

Security is NOT based on OTP entropy alone.

Security is based on:
- device binding
- session binding
- nonce binding
- replay prevention
- single-use validation
- server secret protection

============================================================

LIFECYCLE
------------------------------------------------------------

1. Generate OTP
2. Display to user
3. User inputs OTP
4. Validate (case-insensitive)
5. Invalidate immediately

============================================================

TIMING
------------------------------------------------------------

VISIBLE EXPIRY:
60 seconds

BACKEND GRACE:
90 seconds

============================================================

ATTEMPTS
------------------------------------------------------------

- 1 attempt per OTP
- incorrect OTP invalidates immediately
- new OTP required after failure

============================================================

BOT PROTECTION
------------------------------------------------------------

- rate limiting
- cooldown escalation
- session binding
- nonce binding
- single-attempt enforcement

Cooldowns:
- 60s → 5m → 15m → 1h

============================================================

SERVER SECRET
------------------------------------------------------------

ENV:
AZOTP_SERVER_SECRET=azotp (DEV ONLY)

PRODUCTION:
- MUST use strong random secret
- MUST NOT expose to clients
- SHOULD rotate periodically
