============================================================
I. PURPOSE
============================================================

AZOTP v0.1.0 defines a deterministic, binding-secured,
human-centered OTP protocol with strict canonicalization,
platform isolation, and replay guarantees.

============================================================
II. CORE OTP MODEL
============================================================

FORMAT:

- 4 characters from lowercase a-z alphabet
- base26 encoding

ALPHABET:

abcdefghijklmnopqrstuvwxyz

TOTAL SPACE:

- 26^4 = 456,976

------------------------------------------------------------

CASE RULES:

- internal: normalize to lowercase
- input: case-insensitive (normalized to lowercase)
- display: SHOULD use lowercase

============================================================
III. DERIVATION MODEL
============================================================

A. DETERMINISTIC MODE (RECOMMENDED)

otp = base26(
  BLAKE3-256(server_secret + canonical_context_bytes)
)[0:4]

------------------------------------------------------------

B. RANDOM MODE

otp = base26(CSPRNG_bytes)[0:4]

------------------------------------------------------------

RANDOM MODE REQUIREMENTS:

- MUST construct canonical_context
- MUST compute binding_hash
- MUST store binding_hash
- MUST verify binding_hash during verification

------------------------------------------------------------

HASH DEFINITIONS:

- BLAKE3-256 → 32 bytes
- BLAKE3-128 → first 16 bytes of BLAKE3 output

------------------------------------------------------------

RULES:

- MUST NOT store raw OTP
- MUST bind OTP to context
- MUST use CSPRNG

============================================================
IV. CANONICAL CONTEXT (HARDENED)
============================================================

AZOTP v0.1.0 enforces STRICT BYTE-LEVEL CANONICALIZATION

------------------------------------------------------------

FIELD ORDER (LOCKED):

1. version
2. provider
3. platform_type
4. device_id
5. session_id
6. nonce
7. time_bucket

------------------------------------------------------------

ENCODING FORMAT (MANDATORY):

v:<len>:<value>|
p:<len>:<provider>|
pt:<len>:<platform_type>|
d:<len>:<device_id>|
s:<len>:<session_id>|
n:<len>:<nonce>|
t:<len>:<time_bucket>

------------------------------------------------------------

EXAMPLE:

v:1:1|
p:4:zalo|
pt:3:web|
d:7:web:abc|
s:4:s7d9|
n:4:p4t2|
t:8:28564231

------------------------------------------------------------

RULES:

- ALL fields REQUIRED
- LENGTH MUST be UTF-8 byte-length
- NO field reordering allowed
- NO trimming / normalization allowed
- MUST produce identical byte sequence across systems

------------------------------------------------------------

VERSION RULE:

- version MUST be "1"
- represents canonical format version

------------------------------------------------------------

PLATFORM_TYPE RULES:

- REQUIRED
- MUST be one of:
  "web" | "ios" | "android" | "desktop" | "embedded" | "other"
- MUST be lowercase

------------------------------------------------------------

VIOLATION:

→ INVALID_CONTEXT

============================================================
V. TIME MODEL (LOCKED)
============================================================

time_bucket:

time_bucket = FLOOR(unix_time / 60)

------------------------------------------------------------

RULES:

- MUST be integer
- MUST be included in canonical context
- MUST be identical across systems
- clock drift ≤ ±30 seconds

------------------------------------------------------------

TTL:

- visible: 60 seconds
- backend grace: 90 seconds

============================================================
VI. BINDING MODEL (STRICT)
============================================================

binding_hash = BLAKE3-128(canonical_context_bytes)

------------------------------------------------------------

RULES:

- MUST be computed at generation
- MUST be recomputed at verification
- MUST match EXACTLY

------------------------------------------------------------

STORAGE CONTRACT (MANDATORY):

store:

- otp_hash = BLAKE3-128(otp)
- binding_hash
- expires_at
- used = false

------------------------------------------------------------

RULE:

OTP WITHOUT binding_hash → INVALID SYSTEM

============================================================
VII. VERIFICATION MODEL
============================================================

BEGIN

1. normalize input to lowercase and validate against a-z alphabet
2. compute input_hash = BLAKE3-128(input)
3. recompute canonical_context
4. recompute binding_hash

5. ASSERT:

 - binding_hash matches
 - current_time ≤ expires_at
 - used == false

6. VERIFY:

 constant_time_equal(input_hash, otp_hash)

------------------------------------------------------------

IF success:

- used = true
- authentication proceeds

ELSE:

- used = true (invalidate immediately)

------------------------------------------------------------

RULE:

OTP is SINGLE-USE ALWAYS

============================================================
VIII. CONSTANT-TIME REQUIREMENT
============================================================

function constant_time_equal(a, b):
 if len(a) != len(b):
   return false
 result = 0
 for i in range(len(a)):
   result |= a[i] XOR b[i]
 return result == 0

------------------------------------------------------------

RULE:

- MUST be used for ALL comparisons
- MUST NOT use == or early return

============================================================
IX. NONCE MODEL (STRICT)
============================================================

nonce:

- MUST be cryptographically random
- MUST be unique per challenge
- MUST be single-use

ENFORCEMENT BOUNDARY:

- core package verifies binding_hash + single-use challenge state
- nonce uniqueness MUST be enforced by service storage/transaction layer

------------------------------------------------------------

REUSE:

→ REJECT (NONCE_REUSE)

============================================================
X. DEVICE MODEL
============================================================

device_id:

WEB:

- client-generated UUID
- SHOULD persist (local storage)
- service layer MUST preserve the same device_id for the challenge lifetime

MOBILE / DESKTOP:

- OS/device-backed or app UUID

------------------------------------------------------------

RULES:

- MUST be stable across sessions
- MUST NOT change during challenge
- MUST NOT contain PII
- stability and persistence are enforced by the caller/service layer

------------------------------------------------------------

DRIFT:

→ treated as NEW DEVICE

============================================================
XI. PLATFORM MODEL
============================================================

platform_type:

- REQUIRED
- MUST be:
  "web" | "ios" | "android" | "desktop" | "embedded" | "other"

------------------------------------------------------------

RULES:

- MUST be included in canonical_context
- MUST match between generation and verification

------------------------------------------------------------

SECURITY EFFECT:

- prevents cross-platform replay
- enforces environment isolation

============================================================
XII. ATTEMPT MODEL
============================================================

- MAX ATTEMPTS: 1

------------------------------------------------------------

RULES:

- ANY attempt (success or fail) → used = true
- retry requires NEW OTP

============================================================
XIII. REPLAY PROTECTION
============================================================

ENFORCED BY:

- binding_hash
- service-enforced nonce uniqueness
- service-enforced session semantics
- platform_type binding
- single-use OTP

------------------------------------------------------------

RULE:

ANY reuse → FAIL

============================================================
XIV. CONCURRENCY MODEL
============================================================

REQUIRED:

- SELECT FOR UPDATE
- atomic mutation
- single success guarantee

------------------------------------------------------------

FAIL IF:

- concurrent success occurs

============================================================
XV. SERVER SECRET
============================================================

REQUIRED:

- high entropy
- stored in KMS / Vault
- NOT exposed

------------------------------------------------------------

RULES:

- MUST NOT be logged
- SHOULD support rotation
- MUST remain consistent during TTL window

============================================================
XVI. SECURITY MODEL
============================================================

SECURITY DERIVED FROM:

- binding (provider/platform/device/session/nonce/time)
- server secret
- strict TTL
- single-use enforcement

------------------------------------------------------------

FORBIDDEN:

- plaintext OTP storage
- binding mismatch acceptance
- nonce reuse
- weak RNG
- non-constant-time compare

============================================================
XVII. FAILURE MODEL
============================================================

REJECT IF:

- INVALID_OTP
- OTP_EXPIRED
- OTP_REPLAY
- BINDING_MISMATCH
- NONCE_REUSE
- INVALID_CONTEXT
- platform_type missing or invalid

------------------------------------------------------------

RULE:

FAIL CLOSED ALWAYS

============================================================
XVIII. FINAL INVARIANT
============================================================

AZOTP MUST be:

- byte-level deterministic
- binding-secured
- replay-safe
- single-use
- time-bounded
- concurrency-safe
- platform-isolated

------------------------------------------------------------

IF ANY:

- canonicalization differs
- binding skipped
- nonce reused
- OTP reused
- platform mismatch
- constant-time violated

→ SYSTEM INVALID
