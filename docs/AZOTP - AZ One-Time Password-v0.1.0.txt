AZ One-Time Password

============================================================

I. PURPOSE
============================================================

AZOTP v0.1.0 defines a deterministic, binding-secured,
human-centered OTP protocol with strict canonicalization
and replay guarantees.

It is optimized for:

- trusted-device authentication
- messaging-based verification
- deterministic systems (AIP)

============================================================

II. CORE OTP MODEL
============================================================

FORMAT:

- 4 alphabetic characters (a–z)
- base26 encoding

TOTAL SPACE:

- 26^4 = 456,976

------------------------------------------------------------

CASE RULES:

- internal: lowercase ONLY
- input: case-insensitive → MUST normalize
- display: uppercase recommended

============================================================

III. DERIVATION MODEL
============================================================

A. DETERMINISTIC MODE (RECOMMENDED)

otp = base26(
  blake3_256(server_secret + canonical_context_bytes)
)[0:4]

------------------------------------------------------------

B. RANDOM MODE

otp = base26(CSPRNG_bytes)[0:4]

------------------------------------------------------------

RULES:

- MUST NOT store raw OTP
- MUST bind OTP to context (see Binding)
- MUST use CSPRNG for randomness

============================================================

IV. CANONICAL CONTEXT (HARDENED)
============================================================

AZOTP v1.1 introduces STRICT BYTE-LEVEL CANONICALIZATION.

------------------------------------------------------------

FIELD ORDER (LOCKED):

1. version
2. provider
3. device_id
4. session_id
5. nonce
6. time_bucket

------------------------------------------------------------

ENCODING FORMAT (MANDATORY):

v:<len>:<value>|
p:<len>:<provider>|
d:<len>:<device_id>|
s:<len>:<session_id>|
n:<len>:<nonce>|
t:<len>:<time_bucket>

------------------------------------------------------------

EXAMPLE:

v:1:1|
p:4:zalo|
d:7:web:abc|
s:4:s7d9|
n:4:p4t2|
t:10:2026051509

------------------------------------------------------------

RULES:

- ALL fields REQUIRED
- LENGTH MUST be byte-length (UTF-8)
- NO field reordering allowed
- NO trimming / normalization allowed
- MUST produce identical byte sequence across systems

------------------------------------------------------------

VIOLATION:

→ INVALID_CONTEXT

============================================================

V. TIME MODEL (LOCKED)
============================================================

time_bucket:

time_bucket = FLOOR(unix_time / 60)

------------------------------------------------------------

RULES:

- MUST be integer
- MUST be included in canonical context
- MUST be identical across systems
- clock drift ≤ ±30 seconds

------------------------------------------------------------

TTL:

- visible: 60 seconds
- backend grace: 90 seconds

============================================================

VI. BINDING MODEL (STRICT)
============================================================

binding_hash = blake3_128(canonical_context_bytes)

------------------------------------------------------------

RULES:

- MUST be computed at generation
- MUST be recomputed at verification
- MUST match EXACTLY

------------------------------------------------------------

STORAGE CONTRACT (MANDATORY):

store:

- otp_hash        = blake3_128(lowercase(otp))
- binding_hash    = blake3_128(context)
- expires_at
- used = false

------------------------------------------------------------

RULE:

OTP WITHOUT binding_hash → INVALID SYSTEM

============================================================

VII. VERIFICATION MODEL
============================================================

BEGIN

1. normalize input → lowercase
2. compute input_hash = blake3_128(input)
3. recompute binding_hash
4. ASSERT:

   - binding_hash matches
   - current_time ≤ expires_at
   - used == false

5. VERIFY:

   constant_time_equal(input_hash, otp_hash)

------------------------------------------------------------

IF success:

- used = true
- authentication proceeds

ELSE:

- used = true (invalidate immediately)

------------------------------------------------------------

RULE:

OTP is SINGLE-USE ALWAYS

============================================================

VIII. CONSTANT-TIME REQUIREMENT
============================================================

function constant_time_equal(a, b):
  if len(a) != len(b):
    return false
  result = 0
  for i in range(len(a)):
    result |= a[i] XOR b[i]
  return result == 0

------------------------------------------------------------

RULE:

- MUST be used for ALL comparisons
- MUST NOT use == or early return

============================================================

IX. NONCE MODEL (STRICT)
============================================================

nonce:

- MUST be cryptographically random
- MUST be unique per challenge
- MUST be single-use

------------------------------------------------------------

REUSE:

→ REJECT (NONCE_REUSE)

============================================================

X. DEVICE MODEL
============================================================

device_id:

WEB:

- client-generated UUID
- MUST persist (local storage)

MOBILE / DESKTOP:

- OS/device-backed or app UUID

------------------------------------------------------------

RULES:

- MUST be stable across sessions
- MUST NOT change during challenge
- MUST NOT contain PII

------------------------------------------------------------

DRIFT:

→ treated as NEW DEVICE

============================================================
XI. ATTEMPT MODEL
============================================================

- MAX ATTEMPTS: 1

------------------------------------------------------------

RULES:

- ANY attempt (success or fail) → used = true
- retry requires NEW OTP

============================================================
XII. REPLAY PROTECTION
============================================================

ENFORCED BY:

- binding_hash
- nonce uniqueness
- session_id uniqueness
- single-use OTP

------------------------------------------------------------

RULE:

ANY reuse → FAIL

============================================================
XIII. CONCURRENCY MODEL
============================================================

REQUIRED:

- SELECT FOR UPDATE
- atomic mutation
- single success guarantee

------------------------------------------------------------

FAIL IF:

- concurrent success occurs

============================================================
XIV. SERVER SECRET
============================================================

REQUIRED (deterministic mode):

- high entropy
- stored in KMS / Vault
- NOT exposed

------------------------------------------------------------

RULES:

- MUST NOT be logged
- SHOULD support rotation
- MUST remain consistent during TTL window

============================================================
XV. SECURITY MODEL
============================================================

SECURITY DERIVED FROM:

- binding (provider/device/session/nonce/time)
- server secret
- strict TTL
- single-use enforcement

------------------------------------------------------------

FORBIDDEN:

- plaintext OTP storage
- binding mismatch acceptance
- nonce reuse
- weak RNG
- non-constant-time compare

============================================================
XVI. FAILURE MODEL
============================================================

REJECT IF:

- INVALID_OTP
- OTP_EXPIRED
- OTP_REPLAY
- BINDING_MISMATCH
- NONCE_REUSE
- INVALID_CONTEXT
- INVALID_CONTEXT_VERSION

------------------------------------------------------------

RULE:

FAIL CLOSED ALWAYS

============================================================
XVII. FINAL INVARIANT
============================================================

AZOTP MUST be:

- byte-level deterministic
- binding-secured
- replay-safe
- single-use
- time-bounded
- concurrency-safe

------------------------------------------------------------

IF ANY:

- canonicalization differs
- binding skipped
- nonce reused
- OTP reused
- constant-time violated

→ SYSTEM INVALID
